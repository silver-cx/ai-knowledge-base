# 规则变更

`AGENTS.md` 开头写着当前的规则版本。每次改了页面格式、属性字段或文件夹结构，版本加一，并在这里写清楚两件事：**改了什么**、**旧知识库怎么升级**。

升级时，对 AI 说「**按 docs/规则变更.md 把我的知识库升级到最新版本**」即可。升级前它会先列出要改哪些文件，等你确认；改完跑一遍 `kb-check`，并在 `日志.md` 记一条「升级到规则版本 N」。

## 版本 2（2026-11-18）

这些改动都先在作者自己的知识库里用了一段时间，确认好用才同步过来。

### 改了什么

| 改动 | 为什么 |
|---|---|
| 资料页新增 `范围`：私密 / 工作 / 可公开 | 原来用「本人撰写」兼管隐私，但自己写的公司文档不是个人隐私。一个字段只管一件事 |
| `本人撰写` 改为只做**风格样本**的标记；「不自动并入主题页」只针对关于本人的资料 | 同上；自己写的方案本来就该进主题页 |
| 资料页、主题页新增 `领域`（一个主领域）和 `也相关`；偏好里加一张领域表 | 面板首页按领域分组。分类存在字段里，改名、新增都不用挪文件 |
| 主题页新增 `关于我` | 标出写用户本人的那几页，它们默认不自动更新 |
| 资料页新增可选的 `子类型` | 同一类型再细分，例如 PRD 按业务性质分，不同类型写和审的重心不同 |
| 新增「同一份资料出了新版本」的处理规则 | 原来没有定义；现在原页更新、引用名不变，加 `版本` 和 `### 版本变更` |
| 新增 `项目/` 和「开工 / 收工」 | 同一个项目在多个对话、多个 AI 工具之间交接，只搬提炼后的决定和现状 |
| 新增「收资料」动作 | 在对话里直接把文件、链接、文字发给 AI，先存进 inbox |
| 新增 `plugin/scripts/kb-check.mjs`，体检先跑脚本 | 链接、必填属性这类机械问题不能靠 AI 自查 |
| 体检新增「抽查忠实度」 | 脚本只能查链接对不对，查不了资料页写的数字对不对 |
| 不再写「被这些主题页引用」一节 | 引用关系由面板自动计算，手写的会过时 |
| 安全规则写明：资料会发给模型服务商 | 原来只写「不上传」，容易被误解为全程只在本机 |

**同日补充（不改页面格式，不升版本）**

| 改动 | 为什么 |
|---|---|
| 新增 `plugin/scripts/kb-search.mjs`；问答改为「先搜再读」，主题页超过 10 份或资料页超过 50 份时必须先搜 | 资料多了以后，把主题页全读一遍的消耗会跟着资料量一起涨 |
| 小节名禁止井号、竖线、^、方括号、冒号、百分号，kb-check 会提醒；写了 `版本` 却没有 `### 版本变更` 也会提醒 | 这些字符会让链接在 Obsidian 里断掉；新版本要能看出改了什么 |
| 出处跳转只保证面板和 Obsidian，GitHub 网页上不保证 | 实测 GitHub 会改写小节锚点（例如「成功的PEP包含什么」变成小写的 pep），原来写「GitHub 能跳」不准确 |

**同日补充（二）**

| 改动 | 为什么 |
|---|---|
| 新增「一条结论放哪里」：方法、设计、具体规则三个去向；新建主题页的条件；不重复写；结构性改动只提议 | 一批同一来源的资料进来时，「并入还是新建」原来全凭感觉，实际出现了同一批结论在两个主题页各写一遍、引言份数过时 |
| kb-check 核对引言里写的份数 | 「编自 7 份」这类数字最容易过时 |

### 旧知识库怎么升级

1. **资料页**：每页加 `范围` 和 `领域`。
   - 范围：关于本人的资料填私密；公司内部文档、同事材料填工作；公开资料填可公开。拿不准的填更严的一档，列出来给用户确认。
   - 领域：先根据现有主题页提议 3–5 个领域，用户确认后写进偏好的领域表，再逐页填；有关联的写进 `也相关`。
   - 删掉手写的「被这些主题页引用」一节（如果有）。
2. **主题页**：属性区加 `领域`，写用户本人的那几页加 `关于我: 是`。
3. **偏好**：加「范围和领域」一节（参考 `模板/知识库/偏好.md`）；「关于我本人的资料」改成按范围判断。
4. **文件夹**：新建 `项目/`，从 `模板/知识库/项目/_模板.md` 复制模板。
5. 跑 `node plugin/scripts/kb-check.mjs 知识库`，修掉错误；提醒可以逐步处理。
6. 在 `日志.md` 记一条「升级到规则版本 2」。
