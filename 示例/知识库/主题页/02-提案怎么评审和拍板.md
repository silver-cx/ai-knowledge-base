# 提案怎么评审和拍板

> 三个社区怎么从「有人提了个想法」走到「做或不做」：谁来决定、讨论放在哪、怎么防止讨论没完没了、没有共识时怎么办。

## 结论

1. **先试水，再写正式提案。** 三家都建议先在公开场合问「有没有人提过、有没有机会」，避免花大力气写一份注定被拒的提案〔[PEP 1 · 从一个想法开始](../资料页/PEP-1.md#从一个想法开始)〕〔[Rust 流程 · 写之前](../资料页/Rust-RFC流程.md#写之前)〕。Go 更进一步：第一步只要一个简短的 issue，需要时才写设计文档〔[Go 流程 · 流程四步](../资料页/Go提案流程.md#流程四步)〕。
2. **讨论只放在一个公开的地方。** 实质讨论集中在一个帖子或 issue 里，线下讨论要回填纪要，否则讨论会碎片化、决策无据可查〔[PEP 1 · 讨论](../资料页/PEP-1.md#讨论)〕〔[Rust 流程 · 流程](../资料页/Rust-RFC流程.md#流程)〕〔[Go 流程 · 每周评审](../资料页/Go提案流程.md#每周评审)〕。
3. **决定前留一个固定的「最后发言期」。** Rust 的最终评论期 10 天、Go 的「可能接受 / 可能拒绝」一周——先公示倾向，再正式决定，给反对者最后的机会〔[Rust 流程 · 流程](../资料页/Rust-RFC流程.md#流程)〕〔[Go 流程 · 状态看板](../资料页/Go提案流程.md#状态看板)〕。
4. **没有共识，默认就是不做。** Go 写得最直白：找不到共识通常就拒绝；只有「都同意要解决、但选不出方案」时才上交给更高一层决定〔[Go 流程 · 共识与分歧](../资料页/Go提案流程.md#共识与分歧)〕。Rust 不要求所有人同意，但支持决定的论证必须已经讲清〔[Rust 流程 · 流程](../资料页/Rust-RFC流程.md#流程)〕。
5. **被拒也要留档，并写明理由。** 记录「为什么没做」能防止同样的提议反复出现〔[PEP 1 · 审议与决定](../资料页/PEP-1.md#审议与决定)〕〔[Go 流程 · 状态看板](../资料页/Go提案流程.md#状态看板)〕〔[Rust 流程 · 评审](../资料页/Rust-RFC流程.md#评审)〕。

## 谁来拍板

| | Python | Rust | Go |
|---|---|---|---|
| 最终决定 | 指导委员会，或其委托的一位 PEP-Delegate | 对应领域的小组 | 每周评审组；无共识时交架构师组，再交仲裁人 |
| 引路人 | sponsor（导师角色） | 小组指派的负责人 | 设计文档可配「牧羊人」 |
| 回避 | 有利益冲突的人可能不被批准担任决策人 | — | — |

出处：〔[PEP 1 · 找sponsor](../资料页/PEP-1.md#找sponsor)〕〔[PEP 1 · 审议与决定](../资料页/PEP-1.md#审议与决定)〕〔[Rust 流程 · 流程](../资料页/Rust-RFC流程.md#流程)〕〔[Go 流程 · 设计文档](../资料页/Go提案流程.md#设计文档)〕〔[Go 流程 · 共识与分歧](../资料页/Go提案流程.md#共识与分歧)〕

## 状态比「通过 / 不通过」更细

- **暂定接受**：先上线收集反馈，正式定稿前仍可撤回。但 Python 更倾向于缩小提案范围，而不是依赖暂定状态〔[PEP 1 · 审议与决定](../资料页/PEP-1.md#审议与决定)〕。
- **推迟**：不是否定，是「现在不想、可以等」；如果答案是「将来也不会考虑」，就应该直接关闭〔[Rust 流程 · 推迟](../资料页/Rust-RFC流程.md#推迟)〕。
- **搁置**：等某个信息或修订，并写明在等什么〔[Go 流程 · 状态看板](../资料页/Go提案流程.md#状态看板)〕。
- **快速拒绝**：重复、不可行、作者撤回、已过时，不必走完整流程〔[Go 流程 · 状态看板](../资料页/Go提案流程.md#状态看板)〕。
- **接受 ≠ 排期**：被接受只代表原则上同意，不代表优先级，也不代表有人去做〔[Rust 流程 · 生命周期](../资料页/Rust-RFC流程.md#生命周期)〕。

## 防止流程被拖垮

- **限制在途数量**：Go 先把在途提案推到结论，再从排队区拉新的，避免新工作挤占旧工作导致谁都完不成〔[Go 流程 · 状态看板](../资料页/Go提案流程.md#状态看板)〕。
- **长讨论先写总结**：进入最终评论期前，先发一条总结评论梳理现状和分歧〔[Rust 流程 · 流程](../资料页/Rust-RFC流程.md#流程)〕。
- **评审会不替代讨论**：Go 的每周会议只负责让对的人看到、推动走向结论，讨论本身仍在公开 issue 上〔[Go 流程 · 每周评审](../资料页/Go提案流程.md#每周评审)〕。
